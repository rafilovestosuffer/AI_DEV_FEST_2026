# Sathi Model Card: Cash-Flow Intelligence Stack

Adapted from the reference `docs/model_card.md` for the TypeScript engine
port inside this app, **plus the merged Sathi ML forecaster** (branch
`ml/06-eval`). Companion endpoint: `GET /api/v1/meta/model-card`.

## 1. Model Details

| Layer | Architecture | Version |
| :--- | :--- | :--- |
| **Irregular-flow forecaster** | **LightGBM quantile ensemble (9 quantiles, pinball loss, direct multi-horizon 1–35 days) + recurring-stream detection + block-correlated calibrated path simulation** — trained by the `ml/` pipeline, served in-app by a pure-TypeScript predictor that is **bit-identical to the Python booster** | `fc-2026-09-30-15d8427d` |
| Risk classifier | Logistic regression (L2, deterministic full-batch GD) | `risk-logreg-v1.2` |
| Balance forecast (fallback) | Day-of-month seasonal baseline + seeded stationary block bootstrap (5-day blocks, 400 paths) | `forecast-dayofmonth-v1.1+bootstrap-sim` |
| Goal planner | Monte Carlo over the user's own surplus distribution (2,000 paths, common random numbers) + Platt recalibration of P(goal met) (a=-2.4133, b=0.5291, fitted on the frozen T6 back-test) | `planner-montecarlo-v1+platt-cal` |
| Categorizer | Deterministic rule chain with a reason trace per transaction (no learned labels — ADR-11) | `rules-v1` |

**Forecaster decomposition:** daily wallet net flow = scheduled recurring
streams (salary, rent, bills, supplier; detected from history by the
`recurringStreams` port) + irregular flow (the quantile model). Inputs are
only the user's own transactions dated on or before the forecast origin —
no persona label, persona configuration, ground truth or user id is ever
used as a feature (the salary-day leakage fix, enforced by test). The model
is scale-free (targets divided by the user's 90-day mean gross flow), so one
global model serves every income level. Calibration (split-conformal
widening, within-week path correlation ρ = 0.4, Platt map for P(shortfall))
was fitted on held-out calibration users only. Serving is fail-closed: if
the artifacts are unavailable the deterministic rule/bootstrap baselines
answer instead.

## 2. Intended Use & Invariants

- **Primary use:** short-term liquidity-pressure awareness for mobile-wallet
  users in Bangladesh — safe-to-spend, 7/21-day shortfall risk, fee audit,
  goal feasibility.
- **Purely informational:** Sathi never automates funds movement, never
  approves or denies credit, and never nudges spending. Options are
  presented with trade-offs — never commanded.
- **Explainability:** every insight-bearing response carries an evidence
  block (data window, model versions, labelled assumptions, config hash).

## 4. Persona Fairness (Sathi v1 API personas)

Balanced positive/negative classes across personas; the garment worker
(hero persona) intentionally sits at the knife edge of income vs
obligations — her shortfall-risk signal is the product's core story. The
student persona is a documented low-data case that falls back to persona
priors with `confidence: "low"`.

## 5. Ethical Safeguards & Responsible AI

- **Fail-closed numeric validator** (`llmSafety.ts`): every figure in
  LLM-generated text must match a figure from verified engine output; any
  mismatch causes immediate fallback to reviewed bilingual templates.
- **Prompt sanitizer**: adversarial and money-movement intents are refused
  before any model sees them (both English and Bangla patterns).
- **Privacy by design**: zero production PII; all data is deterministic
  synthetic generation from documented persona assumptions.
- **Assumptions surfaced**: fee math uses the labelled illustrative rate of
  150 bps (min ৳5); essentials ৳350/day; these appear in every evidence
  block, never hidden.

## 6. Synthetic-Data Assumptions (from the reference `docs/assumptions.md`)

- `FEE_CASHOUT_RATE` — 150 bps, min ৳5 (illustrative agent cash-out fee)
- `FEE_DIGITAL_PAYMENT_RATE` — 0 bps (merchant payments assumed free)
- `ESSENTIALS_PER_DAY` — ৳350 (food, transport, utilities share)
- `SHORTFALL_HORIZON_DAYS` — 21 (lookahead cap; product surfaces 7 days)
- `MIN_BUFFER_DAYS` — 3 (planner never drops below this buffer)
- Insufficient-balance rule: inflows apply first each day; an outflow that
  exceeds the balance is skipped (paid late or in cash — invisible to the
  wallet). Keeps all balances non-negative in synthetic history.
